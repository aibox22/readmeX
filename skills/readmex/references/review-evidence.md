# 审查证据与写作取舍

本文件精选上游 README optimization 的证据流程。机械审查只报事实；适用性、真实性和分数由读取源码并执行用例的 agent 判断。

## 干净环境首条路径

在临时目录、独立虚拟环境、容器或项目适合的隔离方式中，从文档说明的前提开始。不要依赖工作区里已经安装的包、未说明的环境变量或缓存产物。

1. 原样执行 README 的安装命令，再原样执行第一个用例。
2. 记录环境、命令、退出状态、实际输出和缺口：运行时版本、系统包、环境变量、准备文件、输出差异。
3. 在 README 明说这些前提或修正命令，并从干净状态重新验证被修复的路径。

规范、数据集和纯资源没有安装命令时，执行它们的第一个真实使用步骤。例如读取数据、复制模板后启动或按示例处理一个文件。环境、网络或工具不支持执行时，A2 记 FAIL（未验证），写明限制；运行中不追加问题，不凭静态阅读授予通过。

## 主张清单

逐条列 README 中的命令、参数、默认值、环境变量、配置键、端点、导出符号、文件路径、版本前提和行为动词；“自动重连”“重试三次”“忽略大小写”都是主张。

| 主张 | 优先证据 |
|---|---|
| 命令、参数、默认值 | 实际入口、参数解析器、配置定义 |
| API、端点、符号 | 定义、导出表、路由和调用测试 |
| 运行时、平台、兼容性 | 清单、CI 矩阵、测试和发布记录 |
| 自动行为、次数、边界 | 实现分支和对应测试 |
| 性能、规模 | 仓库内可重现基准与环境说明 |
| 状态、发布与支持 | 发布记录、提交活动、已有政策和开头收集的事实 |

每条记录 README 位置、对应源码位置、核对结果和处理。路径不存在、签名不符或参数未注册是错误，不能称为文案问题。仓库不能证明、开头也未得到的事实，降级到可证明范围或删除；原主张与原因保留在记分卡。

## 可信写法

- 用依赖数、支持平台、已有测试和明确取舍替代“简单”“飞快”“生产可用”等无法核对的评价。
- 差异写成读者能判断的适用场景，也指出确实需要其他方案的边界，不贬低替代项目。
- 徽章只保留第三方核验的事实，并解释每枚解决哪个采用问题；徽章数量上限是工作约定，不是增长定律。
- 长文档链接出去。图片及动画是补充，关键决定信息和实际指令留在 Markdown；检查 alt 和相对链接。
- GitHub、包注册页或其他已有发布目标分别核对渲染。无法打开的发布页记未验证，不能按假定给予满分。
- 项目实际对外 description、website、topics、social preview 使用同一个有证据的一句话定位。受授权或工具限制时提供具体待应用值并记入报告。

## 不可引用的增长说法

遇到以下三条说法时说明没有可靠出处，不引用或以它们作为修复依据：

- “详细 README 让贡献增加 50%”。
- “star-history 图让 star 转化增加约 15%”。
- “62% 的热门仓库有 GIF demo”。

不承诺比例增长，也不根据访问量判断 README 是否值得修。不加入事后追踪、作者元数据、额外记忆文件、humanizer、兄弟 skill 路由或上游评测问卷。
