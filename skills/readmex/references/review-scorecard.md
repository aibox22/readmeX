# README 审查记分卡

这是人工证据审查的尺度，不是机械脚本的分数。每项附 README 行号、引文、源码位置或实际命令输出。缺证据的阻断项记 **FAIL（未验证）**，不能靠推测补 PASS。

## 五项阻断

| 项 | PASS 的要求 |
|---|---|
| A1 身份 | 前两行有效内容出现项目名和说明，陌生术语有解释或链接。头图或徽章不把身份挤出首屏。 |
| A2 首条操作能跑 | 安装和第一个用例在干净环境按原文执行，前提已说明，命令及结果与文档一致。无安装命令的规范、数据集或模板，验证其第一个实际使用步骤，如读取数据或复制并启动；不能执行则 FAIL（未验证）。 |
| A3 主张可核对 | 每个命令、参数、默认值、环境变量、配置键、端点、导出符号、路径、版本和行为有对应证据；性能、兼容和规模有测试、CI、基准或发布记录支撑。单列不可核对主张数。 |
| A4 状态诚实 | 写明实验、维护中、功能冻结或寻找维护者等实际状态，不暗示超过证据的稳定性和维护承诺。 |
| A5 许可证可到达 | README 写明许可证名称并链接仓库内文件。限制性条款靠前；一行链接足够，不展开许可证全文。 |

## 八项计分

每项 0、1、2 分：0 是缺失或无效，1 是存在但不足，2 是满足要求。

| 项 | 2 分 | 1 分或 0 分的典型情况 |
|---|---|---|
| B1 差异 | 有可核对的比较轴：依赖数量、平台差异、性能证据或明确设计取舍。 | 1：只有“简单、快速”；0：没有差异。 |
| B2 到首条可复制命令的距离 | 首屏附近、前 400 词内出现实际使用命令或等价首个操作。 | 1：长前言之后才出现；0：没有可操作的例子。中文词数由工具启发式估算，仍需检查首屏。 |
| B3 可运行用例 | 完整用例说明输出或效果，同一用例在仓库内有文件可直接运行。 | 1：可运行但没有仓库文件或结果说明；0：只有 API 签名或不能运行。纯资源以可复现首个使用步骤等价判断。 |
| B4 漏斗顺序 | 身份→差异→用法→安装→细节→背景；读者随时退出都未漏掉会改变决定的信息。 | 1：内容齐但关键判断靠后；0：无法迅速判断适用性。 |
| B5 徽章纪律 | 最多四枚，均可由第三方核验并回答读者的实际问题；零枚也可以通过。 | 1：稍多但每枚有用；0：徽章墙、口号或未核验的信号。 |
| B6 图片不独占关键信息 | 图片都有有意义的 alt，指令、命令和决策事实也出现在 Markdown 文字中。 | 1：有 alt 但文字补充不足；0：关键事实只在图片/动画里或缺 alt。 |
| B7 发布处链接可用 | 相对链接在默认分支可用，实际检查已有其他发布目标的渲染；只有 GitHub 发布时检查该唯一目标即可。 | 1：本地可用但远端/其他发布目标未验证；0：坏链或去掉 HTML 后丢失关键内容。 |
| B8 内容不过载 | 长参考、教程、配置表和社区流程以链接指向文档；README 聚焦采用决策。 | 1：有少量溢出；0：把长文档和社区流程全部内联。章节数只是线索，不是分数。 |

通过条件固定为 **A1–A5 全部 PASS，B1–B8 ≥14/16**。16 分与 14 分通过线是此 skill 的工作尺度，不是研究标准。未知事实不能用高分抵消。

## 修复顺序

只按单位时间回报列顺序，默认：

`状态说明 > 安装路径 > 主张核对 > 差异段落 > 徽章清理 > 漏斗重排`

据真实证据重排：明显坏掉的安装或不可核对主张必须修；现成的差异证据会降低差异段落成本；冷读者因为没有读到关键信息而答错时，提高结构调整优先级。报告说明重排原因，不同时列“难度”“损害”“价值”三套榜单。

仅公司或采购受众列企业信号，不单独加分。按回报顺序检查已有事实：

`支持预期 == 发布节奏 > 安全政策 > 已知采用者 > 供应链证明 > 治理与维护者深度 > 基金会归属`

没有证据就写缺失，不建议为了 README 临时承诺服务级别、获得客户背书或改变治理结构。

## 冷读者五问

给未见过仓库的人或无仓库上下文的新 agent 只看 README，60 秒内回答；五问全对通过。记录实际回答，不能由作者代答。

1. 这是什么？（A1）
2. 为什么选择它，替代已经知道的方案？（B1）
3. 是否符合语言、平台和许可证限制？（A5、B7 及要求说明）
4. 第一条要运行的命令或实际使用步骤是什么？（A2、B2、B3）
5. 项目是否仍活跃？（A4）

## 报告形状

```text
README 审查 — <仓库>（受众：个人/公司/两者）
阻断：A1 PASS · A2 FAIL（未验证：网络不可用）· A3 FAIL · A4 PASS · A5 PASS
主张核对：2 条不可核对；逐条列主张、来源/缺失、处理结果
计分：11/16（B1 0, B2 2, B3 1, B4 2, B5 0, B6 2, B7 2, B8 2）
结论：未通过；A2/A3 阻断
冷读者：3/5；记录实际回答及对应修复
修复顺序：按单位时间回报排列，附证据与重排原因
被删/降级事实：主张、原位置、原因、修改后内容
企业信号：仅公司受众；已有、缺失及证据
仓库外观：description、website、topics、social preview 的实际修改或具体待应用建议
限制：命令未执行、发布页无法打开、权限不足等
```

在 `<target>/.readmex/review/scorecard.md` 保留诊断与最终复评分数，原始机械结果在同目录 `audit.txt`。单独审查的诊断交付后等用户同意才改写；全流程已有授权直接继续。
