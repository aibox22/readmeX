# 优化视觉精选

精选自 oil-oil 的 beautify-github-readme。Markdown 承载内容；SVG 承载可维护的布局；生图素材和 GIF 只在明确同意时使用。

## 内容与英雄图

- 首屏有项目名、普通读者能理解的一句话价值和强证据。徽章、巨大的 Logo 和装饰不能遮住身份。
- 真实输出、截图或小用例先于抽象承诺。差异写机制与取舍，避免泛泛的“简单、快速”。
- 英雄图的文字、题材、右侧素材与构图来自项目本身。删掉项目名称后，不应能把同一英雄图直接给无关项目。
- 证据放进英雄图后看不清，就在简洁头图后单独放证据板；保持可读性比把所有内容塞在一张图里更重要。
- 整页刷新遵循已审查的身份→差异→用法→安装→细节→背景顺序。长教程、配置参考和社区流程以链接承接。
- 模块各有沟通任务。正文、命令、链接、关键限制和决策事实不能只存在于图片里。

## GitHub 画布

使用 GFM 和必要的简单 HTML 对齐/尺寸属性，推荐：

```html
<p align="center">
  <img src="readme/assets/hero.svg" width="100%" alt="项目名及其主要价值">
</p>
```

SVG 约束：

- 完整宽度 `viewBox="0 0 1200 H"`，自带浅色背景，重要内容离边缘足够远。
- 主要图标签至少 20、辅助至少 18、章节标题至少 40 SVG 单位。900 宽时分别约 15、13.5、30 CSS 像素；360 宽时再判断实际阅读效果。
- 用系统字体，例如 `-apple-system, BlinkMacSystemFont, Segoe UI, PingFang SC, sans-serif`，以字号和字重形成层次。
- 大模块有有意义的 `<title>` 和 `<desc>`；Markdown 或 HTML 图片有描述用途的 alt。
- 使用形状、路径、文字、渐变、剪裁和简单变换。禁止 script、foreignObject、事件处理器、远程字体和外部样式表。公开的 SVG 不依赖远程或本地栅格资源。
- GitHub 不播放 SVG 动画。动图用 GIF，同时保留静态 SVG；不要让动画携带唯一的信息。
- 900 和 360 宽预览均必须可读；稠密图需简化或拆分，完整说明保留在 Markdown。

图的背景保证 GitHub 浅色/深色页面中的对比度。避免装饰性边框和大阴影，除非冻结的项目视觉主题确实需要。

## 质量条

1. 首屏无需上下文就能理解项目。
2. 视觉系统、母题和英雄图属于这个项目；每个模块都有沟通任务。
3. 真实证据先于主张，没有发明功能、采用者或性能。
4. README 更短或更清楚，图片加载失败时仍有意义。
5. 命令、链接、关键事实和限制可在 Markdown 读取。
6. 900/360 两种宽度均检查字号、裁切、密度和节奏；必要细节可在图下文字读取。
7. 本地图片存在、alt 有意义、SVG 安全且自带背景，发布 PNG 无缺失素材。
8. GIF 安静、静止阶段稳定、循环无跳变，静态回退存在；帧文件清理。
9. 素材范围不改写或嵌入 README；整页范围不添加署名或 showcase 宣传。

`readme_view_audit.py` 是机械检查；它不证明移动端可读性、图的事实正确性或构图质量。
